# REIN 全レース保存・公開準備（2026-09-27）

## 今回の変更

- JRA開催日の予想をサーバーで一括取得し、全利用者共通のスナップショットとして保存。閲覧や手動保存は不要。
- 「この予想を保存」「端末の記録を出力」を廃止。画面の「自動保存・答え合わせ」はサーバー履歴を読む。
- 発走前の予想と人気を保持し、結果は別テーブルで管理。同一レースの最終発走前予想を集計し、上位同着・出走馬変更・発走後の再計算を除外。
- 人気比較図を右＝人気上位、上＝REIN上位へ変更。人気以上の評価は左上に位置する場合がある。
- 馬メモは個人用のまま。サーバーへ編集した馬だけを送信し、別端末の無関係なメモを上書きしない。過去の個人保存データは削除しないが、共通成績には混ぜない。

## 取得と表示

| 対象 | 更新・保存方針 |
|---|---|
| JRAの発走1時間前〜発走前 | 10分間隔。直近8分以内の取得は重複実行しない |
| それ以前のJRA予想 | 3時間間隔で更新。未保存レースは優先して埋める |
| 翌日予想 | 16時以降に対象化。6時間間隔 |
| 結果 | 発走10分後から照合。夜と翌朝に未完了分を補完 |
| JRA・NARの日次データ | 22:35 JSTに当日分、翌06:35 JSTに未完了の前日分。GitHub scheduleは遅延する場合がある |
| 日次アーカイブ | 結果・最終オッズ・払戻・元ページ・取得監査を圧縮し、既存の非公開Storageへ保存。SHA-256再ダウンロード照合後に完了扱い |
| ブラウザー表示 | 共通ランタイムキャッシュ→永続スナップショットの順に読み込み。古い値を先に返して裏側で更新。未準備のみ202と上限付き再確認 |

日次取得は開催カレンダーで対象日だけを絞る。JRAの券種別オッズも、対象レースに属するタブだけを巡回し、ナビゲーションにある前日・他場へ広げない。正しく未開催と判定できた日は小さな監査記録だけ残す。通信失敗や解析失敗を未開催には扱わない。検証済みで現行形式のアーカイブは再取得しない。取得処理の変更時にも完了確認を1回実行する。

NARの本番予測画面は従来どおり準備段階。今回のNAR対象は全開催日の結果・オッズ等の蓄積であり、未検証のNAR予測モデルを公開する変更ではない。日次取得は学習用データを蓄積する。新データによるモデルの自動採用は行わず、時系列検証を経て更新する。

## 費用の設計

新規の有料プロジェクト・常駐サーバー・DBプランは追加しない。既存VercelとSupabaseを使う。

- 公開リポジトリの標準GitHub-hostedランナーで日次収集する。モデル学習用の重い依存をインストールしない。
- 大量データはGitHubのArtifactに重複保存せず、既存Storageへ直接保存。実行ログには件数と監査情報のみ残す。
- NARの日付絞り込みを月内の全開催場ページ取得より前に移し、日次収集で月全体を巡回しない。
- 閲覧者が増えても同じレースを重複計算しないようDBの原子的な取得ロックを使う。
- 全レスポンスの履歴を無制限に複製せず、表示用は最新・発走前・前日版、比較履歴はコンパクトな予想項目を保存。運用ログだけ31日で期限切れにする。
- 廃止済みのルート側VercelプロジェクトのGit自動デプロイを無効化。`rein-web`側の本番mainデプロイは維持する。

料金の基準（2026-09-27公式確認、実際の契約・請求を示すものではない）:

| サービス | 基準と影響 |
|---|---|
| GitHub Actions | 公開・標準ランナーの実行時間は無料。非公開Freeの無料枠は2,000分/月、Proは3,000分/月。Linux 2-core超過は$0.006/分 |
| Vercel Cron | Cron自体の追加料金とは別にFunctionsの使用量が計上される。10分間隔はPro以上。既存のプランは今回変更しない |
| Supabase | Pro公示価格は$25/月〜。DBは8GB/プロジェクト、ファイル100GBを含む。ファイルの超過単価$0.0213/GB/月。実利用・転送・Computeで増減する |

例: 私有化した標準Linux処理が4,000分/月なら、Freeの2,000分枠との差2,000分は$12/月（ほかのリポジトリ利用・Artifact等を含まない）。将来も収集専用を公開に保てば、この収集実行分の有料化を避けられる。現行の実行時間・保存増分を測るまでは月額総額や削減率を断定しない。

## 非公開化は地方競馬の過去取得完了後

単一リポジトリの一部フォルダーだけを非公開にすることはできない。次の分離を行う準備とする。今回はリポジトリの公開設定を変更しない。NAR過去取得の保存先・既存の再開ルールも維持する（既存Actionsのパス指定に該当するコード更新では再開ジョブが自動起動する）。

| リポジトリ案 | 内容 |
|---|---|
| 公開・収集専用 | 低負荷の取得コード、データ形式、日次Actions。生データ・個人情報・秘密鍵は置かない |
| 非公開・REIN本体 | Web、推論ロジック、学習・特徴量・検証コード、運用設定 |
| サーバー側 | 学習済みモデル、元データ、全レーススナップショット、ユーザー別メモ |

移行時には取得完了件数を照合し、GitHub OIDCの許可を新しいrepository ID・workflow・mainに絞り直す。すでに公開済みのコードや複製は、後で私有化しても回収できないため、新たな秘密情報を公開履歴に追加しない。

## 公開前の具体的な修正・検証

- 新規共有テーブル6個はRLSを強制し、anon/authenticatedにはテーブル・書込RPCの権限を与えない。
- Vercel署名付きIDによるバックエンド操作、GitHub署名付きIDによる限定パスへの日次保存。恒久的な管理キーをブラウザーやActionsへ配らない。
- 共有履歴APIもJRA利用権チェックの対象。ユーザー向けAPIはprivate/no-storeとし、サーバー内部キャッシュのみを共用。
- 47件のJavaScriptテスト、日次取得・JRA/NARパーサー12件、TypeScript・本番ビルドを確認。
- 実DBで、予想不変性、二重登録、結果の別管理、取消除外、二重ロック、権限をトランザクション内で検証。架空レースはROLLBACKし残さない。
- ブラウザーのAPIフィクスチャで320/360/390/768/1280pxを確認。横はみ出し・隊列タブ重なり・JS例外なし。新しいブラウザーでも共通成績とサーバーの馬メモを表示。
- 新規テーブルのAdvisorはサーバー専用のため「RLS有効・ポリシーなし」INFO。別サービスWAKEの既存WARNはこの変更では操作していない。
- 実データの日次初回取得と本番デプロイ結果はPR/Actions実行に記録する。モデルの的中率向上を今回の保存改善の成果として主張しない。

## 初回運転で修正した点

- Storageで未保存オブジェクトを調べるAPIがエラーを返したため、限定ディレクトリの完全一致確認へ変更。未保存とサービス障害を区別する。
- JRA当日ページの開催・結果・馬ID・オッズの識別子は過去ページと異なる。両形式に対応し、2026-09-27の中山12レース166頭、阪神12レース141頭を実ページで解析確認。各場の単複表も取得確認。
- 初回JRAで誤って未開催扱いとなった旧形式アーカイブは再利用せず、形式番号付きで自動再取得する。NARの既存検証済みアーカイブは引き続き再利用する。
- Actionsが本番切替直前に照合APIへ到達した場合は、短時間の再試行で切替を待つ。
- 日次の全券種アーカイブと、画面用スナップショットの補完を独立したジョブにする。重い収集を待たずに画面データを保存し、JRA・NARごとの同時取得制御で重複を防ぐ。
- 既存NAR途中分析で、約5分後に署名付き認証が期限切れとなる401を確認。ダウンロード中も4分以内に認証を更新する。また新チャンク到着時は実行中の分析を中断せず、最新の後続処理を待機させ、同じダウンロードのやり直しを抑える。過去取得本体のワークフローはこの修正で変更しない。
